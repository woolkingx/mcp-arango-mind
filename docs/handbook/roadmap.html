Roadmap

Current Boundary

The current runtime has landed the split surface: mcp.mcp, mcp.arango, and mcp.tool.*. The roadmap now focuses on deepening templates, atlas projections, graph/view readiness, and live ArangoDB proof coverage without widening the MCP action surface.

interface owner
  -> surface root
  -> tool owners
  -> ArangoDB API owner

Async Migration Source

PCfVW/mcp-arangodb-async issue #2 is the external migration-rationale coordinate: preserve the ArangoDB multi-model advantage while avoiding large always-loaded MCP tool catalogs.

Surface Migration Order

  1. Keep this handbook target as the source of truth.
  2. Introduce mcp.mcp and mcp.arango with small verbs.
  3. Split async categories into mcp.tool.* owner schemas.
  4. Create mcp.tool.template before adding template CRUD.
  5. Leave old names as temporary aliases only when tests require migration safety.

Async Migration Order

  1. Declare the owner schema first.
  2. Keep actions small and move operation names into payload.target.
  3. Add fixtures and proof gates.
  4. Move operator code behind the owner transition.
  5. Expose through MCP/CLI as interface projection.

GATE-ROADMAP-01 Async Functions Migrate As Tool Owners

Before migrating an async/ function, the change must name the tool owner, owned schema, legal transitions, command envelope, action payload, allowed ArangoDB API calls, evidence output, and proving tests.
