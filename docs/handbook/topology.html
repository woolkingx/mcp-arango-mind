System Topology

Principle

data -> schema -> boundary -> legal edge -> operator -> evidence

The only legal runtime path is interface owner to surface root to tool owner to ArangoDB API owner. API-only behavior is still a minimal tool owner.

Legal Map

client
  -> MCP interface owner
       stdio or HTTP transport
       mcp/schema/mcp.schema.json
  -> tool owners
       tools/schema/tools.schema.json
       target surface: mcp.mcp / mcp.arango / mcp.tool.*
       command envelope: toolName/action/payload
  -> ArangoDB API owner
       arango/schema/arango.openapi.schema.json
  -> connection owner
       config, env, auth, retry, HTTP fetch

Allowed Edges

server.mjs -> createCore(config)
transport -> core.handle(message)
core -> bus.send('validate', message)
core -> bus.send('route', validated)
protocol -> tools.callTool(toolName, { action, payload })
tools -> resolve surface root: mcp.mcp | mcp.arango | mcp.tool.*
tools -> arangoApi.callOperation(operationId, operationArgs)
arango-api -> connection.request(method, path, request)
connection -> fetch(url, request)

Forbidden Crossings

  • MCP protocol decides tool truth.
  • Arango OpenAPI stores tool transitions.
  • The bus interprets owner payload fields.
  • A huge Arango or async operation namespace becomes one oversized action enum.
  • Connection config mutates through an unnamed tool owner.
  • async/ behavior becomes master/ truth without migration gates.
