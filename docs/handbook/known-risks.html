Migration Evidence

PCfVW/mcp-arangodb-async issue #2 is an external evidence coordinate for the migration posture. It records the practical pressure that motivated this project direction: ArangoDB is valuable for agent systems because documents, graphs, search, and operational metadata can live in one substrate, but the MCP surface must avoid loading a large operation catalog into every interaction.

Local consequence: keep broad database capability behind searchable surfaces, move repeated workflows into templates, and expose knowledge structure through read-only atlas projections. This evidence supports GATE-SURFACE-01, GATE-ATLAS-01, and GATE-ROADMAP-01.

Debugging Order

  1. Fix handbook drift before chasing code symptoms.
  2. Name the owner boundary before changing handlers.
  3. Check whether the change belongs to mcp/, arango/, or tools/.
  4. Keep current OpenAPI and MCP reference gates locked by tests.
  5. Keep connection mutation out of MCP until it has a tool schema.
  6. Live-test real MCP host behavior after unit gates are stable.
