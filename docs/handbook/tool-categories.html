Tool Categories

Principle

mcp.tool.* is the local/custom owner space. Categories follow the old async/ split when that split names a real owner, but the handbook may split a category further when lifecycle data needs its own owner.

Template Owner

The old async line mounts template_execute under admin and reads JSON files directly. That route may remain as an alias during migration, but template lifecycle is not admin data.

  -> create/update/remove

Curated Template Policy

Templates are stable intent interfaces, not an archive of old AQL snippets. A template should collapse a recurring workflow into a named target with parameters, defaults, and an evidence envelope. Substrate choices such as ArangoSearch views, named graphs, or direct collection scans may evolve behind the target without changing the caller contract.

TemplateOwnsSubstrate
memory.viewTime-ordered notes projection with optional query, tag/type filters, and root/depth neighborhood.notes plus optional edges traversal; may later use ArangoSearch view or named graph optimization.

This chapter intentionally stays above the 200-line split checkpoint because it is one owner/gate reference for mcp.tool.* category boundaries.

Runtime Rule

Each category keeps a small verb set. The category target namespace holds detailed operations, so the MCP descriptor stays readable while the payload remains precise.

GATE-TOOL-CATEGORY-01 Category Owns Its Lifecycle

A category may execute, mutate, or describe only the data nodes it owns. Cross-category aliases must name the canonical owner and remain removable.
