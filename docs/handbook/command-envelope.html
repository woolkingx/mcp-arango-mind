Command Envelope

Canonical Shape

All cross-owner tool commands use one flattened envelope. The envelope names the tool owner and action; the payload remains owned by the action schema.

{
  "toolName": "mcp.tool.collection",
  "action": "call",
  "payload": {
    "target": "insert",
    "params": {}
  }
}

Field Owners

FieldOwnerRule
toolNameTools activation rootMust resolve through the active schema tree.
actionTool owner schemaMust be declared by the tool owner.
payloadtoolName + action schemaMust be an object and validate against the action payload schema.
payload.targetAction payload ownerUsed only by actions whose payload naturally selects a nested target, such as mcp.arango.exec or mcp.help.get.
payload.paramsAction payload ownerUsed only when the selected target owns its own nested input, such as raw OpenAPI or template execution.

MCP Projection

MCP tools/call
  params.name = toolName
  params.arguments = { action, payload }

internal command event
  data = { toolName, action, payload }

owner execution
  schema = reachable tool owner schema
  action = schema.$defs.actions.properties[action]
  payload = schema-backed object

Payload Object Rule

Large values, non-JSON bodies, secrets, and binary-like data do not change the envelope. They become fields inside the action-owned payload object.

{
  "toolName": "mcp.arango",
  "action": "exec",
  "payload": {
    "target": "executeCode",
    "params": { "_body": "return 1" }
  }
}

{
  "toolName": "mcp.arango",
  "action": "exec",
  "payload": {
    "target": "importData",
    "params": { "$vault": "vault://payloads/import-001" }
  }
}

GATE-ENVELOPE-01 Envelope Holds

The bus may route commands but must not interpret action payload fields. The tool owner validates action and payload before execution.
