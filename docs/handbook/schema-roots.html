Schema Roots

Principle

The project has three root schema families. Each family owns only its own data shape. Runtime code may project these schemas, but must not move ownership into handlers.

Root Map

RootOwnsCanonical FileReference
mcp/MCP protocol API shapes, tool descriptors, requests, responses, content envelopes.mcp/schema/mcp.schema.jsonreference/mcp/2025-11-25.schema.json
arango/Raw ArangoDB HTTP API operation shapes and operation ids.arango/schema/arango.openapi.schema.jsonreference/arango/community.openapi.json
tools/Local MCP tool owners, custom payloads, transitions, effect metadata, and activation reachability.tools/schema/tools.schema.jsonlocal owner schemas

Owner Rule

mcp schema root
  -> interface shape only
arango schema root
  -> raw API shape only
tools schema root
  -> local tool owner truth

When a field is not part of the official MCP API or the ArangoDB OpenAPI, it belongs to a reachable tool owner schema or another named data owner.

GATE-SCHEMA-ROOT-01 Root Ownership Holds

A new schema file must name its root family, source reference, owning operator, downstream chapter, and proof command before it changes runtime behavior.
