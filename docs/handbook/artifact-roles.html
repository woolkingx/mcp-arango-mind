Artifact Roles

Principle

Every durable claim needs exactly one artifact owner. A claim may be projected elsewhere, but projection is not ownership.

Role Map

ArtifactOwnsMust Not
handbookArchitecture, topology, owner boundaries, gates, roadmap.Become a task log or duplicate generated schema details.
CLAUDE.mdBoot card, local invariants, navigation, latest decisions.Hold the architecture spec.
docs/plan/Task order, file targets, commands, verification boundary.Create architecture semantics.
schemaMachine contract and legal data shape.Invent transitions that the handbook does not admit.
codeExecutable projection of handbook + schema truth.Hide owner decisions inside handlers.
testsProof and regression evidence.Become a second runtime architecture.
READMEPublic quickstart and repository entry.Compete with handbook architecture truth.

Entry Order

  1. Read CLAUDE.md for local constraints.
  2. Enter through handbook index.
  3. Open the owning chapter.
  4. Read the local execution plan when present; docs/plan/ is not part of the public release surface.
  5. Change schema, code, and tests only after the owner is clear.

GATE-ARTIFACT-01 Claim Has One Owner

A change passes only when the durable claim is placed in one artifact owner and every other artifact is only a projection, pointer, or proof.
