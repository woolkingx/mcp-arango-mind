Tool Surfaces

Principle

The MCP-visible tool name identifies the owner root. The action stays small. Large operation catalogs are routed through payload.target and payload.params.

Target Surface

MCP ToolOwner RootPurpose
mcp.mcpmcp/Expose MCP reference metadata and small MCP-facing helpers.
mcp.arangoarango/Expose raw ArangoDB API discovery and generic operation calls.
mcp.tool.*tools/Expose local/custom tool owners split by category.

Action Budget

Actions are control verbs, not the full operation namespace. A catalog with dozens or hundreds of operations must not become a huge enum in the MCP tool descriptor.

{
  "action": "call",
  "payload": {
    "target": "collection.insert",
    "params": {}
  }
}

Small Verb Set

ActionMeaningPayload Owner
listList known targets in this surface.surface root
searchFind targets by keyword, category, or capability.surface root
describeReturn schema, gate, or metadata for one target.target owner
callExecute one target with target-owned params.target owner

Current Runtime Boundary

The current code exposes all three surfaces: mcp.mcp, mcp.arango, and the seven mcp.tool.* categories (template, database, collection, view, graph, admin, atlas). The target surface taxonomy is fully realised.

GATE-SURFACE-01 Surface Action Budget Holds

A surface can add a new action only when it is a root-level control verb. Operation-specific behavior belongs in payload.target or a smaller tool category.
