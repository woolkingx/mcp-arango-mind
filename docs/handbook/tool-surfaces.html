Tool Surfaces

Principle

The MCP-visible tool name identifies the owner category. The category schema directly owns its action list, event-shaped examples, payload fields, descriptions, and help page definitions under $defs. Raw OpenAPI remains under mcp.arango; local category tools expose concrete actions such as insert, find, and aql_query directly.

Target Surface

MCP ToolOwner RootPurpose
mcp.mcpmcp/Expose MCP reference metadata and small MCP-facing helpers.
mcp.arangoarango/Expose raw ArangoDB API discovery and generic operation calls.
mcp.tool.*tools/Expose local/custom tool owners split by category.

Category Actions

For mcp.tool.*, actions are the category operations. The schema ref boundary is only the category file; action-specific params stay as fields on that category payload object. The help projection uses the same event shape: {target, action, payload}. No nested oneOf, anyOf, or target-dispatch schema language is introduced.

{
  "action": "insert",
  "payload": {
    "collection": "notes",
    "document": {}
  }
}

Schema Shape Discipline

Each MCP tool's advertised input_schema is direct and category-owned: action enum, payload object with known fields, and a compressed one-line action list shaped like mcp.tool.collection(action=insert, payload={...}). Full action help is kept in the same category schema under $defs.actions and exposed by mcp.help. No top-level allOf, oneOf, anyOf, or if/then/else appears in any advertised tool schema.

Reasons:

  • The Anthropic API rejects top-level allOf/oneOf/anyOf in tools.*.custom.input_schema; encoding conditional payload requirements there breaks tool registration.
  • Conditional payload requirements are runtime owner concerns. The category schema lists available fields and the action help schema lists the required subset for humans and agents.
  • Unmigrated actions stay out of the advertised action enum and mcp.help list. mcp.help get may return an explicit unavailable page for an old action, but it must not present that action as normally callable.
  • Rule prose, routing tips, and when-to-use guidance live in mcp.help or the wx-arango skill. MCP schema introspection is the category action/field surface, not the long-form rule book.

Current Runtime Boundary

The current code exposes all three surfaces: mcp.mcp, mcp.help, mcp.arango, and the seven mcp.tool.* categories (template, database, collection, view, graph, admin, atlas). The target surface taxonomy is fully realised.

GATE-SURFACE-01 Surface Action Budget Holds

A surface can add a new action only when it is a root-level control verb for that owner. Category behavior belongs in concrete action + payload pairs; payload.target is reserved for actions whose own payload selects a nested target, such as raw OpenAPI, template execution, atlas profiles, or help lookup.
