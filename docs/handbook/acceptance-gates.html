GATE-BOUNDARY-01 Owner Boundary Holds

Any new MCP action, resource, config mutation, or custom behavior must name its data owner and proving test before implementation.

GATE-SCHEMA-ROOT-01 Root Ownership Holds

Schema changes must stay under mcp/, arango/, or tools/ according to the data shape they own.

GATE-RUNTIMESCHEMA-01 Runtime Collection Schema Holds

Runtime collection schemas under config/schemas/*.json own project document shape and schema extensions such as x-first-level. They are consumed by the schema registry and atlas projections, not treated as ArangoDB collection-schema registration templates.

The registry proof must show every valid runtime schema file is loaded by collection name, and invalid runtime schema files fail the schema2object gate instead of being silently skipped. The async migration set is access_logs, edges, notes, tag_edges, tags, and todos; master must not narrow the active set to a single collection unless the handbook explicitly retires the others.

notes.type proof must show the runtime schema exposes the allowed first-level roots and that atlas.types projects those roots without inventing a separate rule. Collection write proof must show mcp.tool.collection applies runtime validation by collection owner boundary before Arango dispatch, without hardcoded operation-name rule ownership.

GATE-SURFACE-01 Surface Action Budget Holds

MCP-visible tool surfaces keep compressed action indexes. Category tools expose direct action + payload pairs; raw OpenAPI, template, atlas, and help actions use payload.target only when their own payload selects a nested catalog entry.

GATE-TOOLS-01 Tool Activation Is Reachability

New tools enter by reachable owner schemas under tools/schema/tools.schema.json. tools/list and mcp.help may advertise only actions that are implemented or explicitly marked unavailable; schema-owned help must not present unmigrated actions as normal callable actions.

GATE-TOOL-CATEGORY-01 Category Owns Its Lifecycle

Local tool categories own their data lifecycle. Template CRUD belongs to mcp.tool.template, not to admin metadata.

mcp.tool.collection keeps generic collection/document/index operations discoverable through category search and describe. Its collection entry applies runtime collection schemas by params.collection before document writes dispatch to Arango. Runtime collection schemas are proved by GATE-RUNTIMESCHEMA-01; Arango OpenAPI schema payloads remain raw database operation shapes.

node --test tests/tool-category-owner.test.mjs tests/arango-api.test.mjs tests/collection-schema-live.test.mjs

GATE-ATLAS-01 Atlas Stays Read-Only

mcp.tool.atlas may project the notes and edges collections, type coordinates, topology, and readiness hints through AQL. It must reject collection overrides and roots outside notes/<key> for rooted graph profiles; graph/view/index mutations stay in their owning tools.

atlas.types is the only atlas target for type-coordinate views. Table, suggestion, and tree output are selected by params such as mode, query, tags, root, depth, and examples, not by adding separate atlas targets.

The atlas AQL proof must include a stdio JSON-RPC fixture replay through server.mjs. Owner-level mocks may prove query construction and envelopes, but they do not prove AQL parser validity, bind variable compatibility, or MCP transport composition.

node --test tests/atlas-owner.test.mjs tests/stdio-e2e.test.mjs
